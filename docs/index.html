Hybrid search that finds the exact symbol and what you meant

with weighted rank fusion with exact matching for symbols and IDs with an optional ColBERT reranker that skips the reranker when sources agree in browsers, Bun and Node.js measured in 20 languages

defuss-search runs a lexical and a vector retriever over the same document IDs and fuses their rankings. Exact promotion keeps a document whose symbol or ID equals the query on top, weighted rank fusion orders everything after them, and an optional ColBERT stage reorders the top 25. Every result carries the ranks and scores behind its position.

Exact where it matters

Symbols, IDs and error codes need exact matches. With exact: 'promote', a document whose exact field equals the query ranks first, even when the query vector points at another one. Stemmed fields get an unstemmed companion, so a word as written beats words that only share its stem.

Fusion or a cascade

Fuse independent lexical and vector top-25 lists with weighted reciprocal rank fusion, or rescore one source's candidates with the other: fusion, vector-first or lexical-first, chosen per query.

Neural only where it helps

searchPreset('reranked') lets ColBERT reorder the top 25 and skips the model when the vector winner already ranks first by a clear margin and lexical retrieval agrees. searchPreset('efficient') runs no reranker at all.

Every rank explained

Each hit reports its rank and raw score in every source, each fusion contribution and the reasons for a promotion. Each response says whether the gate ran or skipped the reranker, and why.

Small core, optional peers

The root entry has no runtime dependencies and ships as ESM and CommonJS with TypeScript types. Adapters for defuss-lexicalsearch, defuss-vectorsearch and ColBERT load only when you import them; your own retrievers and rerankers plug in the same way.

How it works

Retrieve twice, fuse once, rerank only when needed

The lexical retriever gets the query text, the vector retriever its embedding; both return their top 25 within the same eligible IDs. Pure functions fuse the two rankings and apply exact promotion and source coverage. The gate then decides whether ColBERT reorders the top 25, and the policies apply again before the page is cut.

Fusion default

Retrieve both sources independently, deduplicate the union and combine the ranks. A document that only one source finds can still win.

Vector first

Retrieve semantic candidates, then order that pool with the lexical index. Candidates without a lexical hit stay in the tail.

Lexical first

Retrieve lexical candidates, then rescore those IDs by vector similarity. The second stage cannot recover a candidate the first one missed.

The ranking contract, in order

Final rank is authoritative; scores from different stages are not comparable, so each hit states its scoreKind.

  1. retrieve each source returns its top 25 among the eligible IDs
  2. fuse weighted reciprocal rank fusion, or the second stage of a cascade
  3. exact with exact: 'promote', literal matches move to the front
  4. coverage balance reserves early ranks for each source's best candidate
  5. gate a clear vector winner that lexical retrieval agrees with skips the reranker
  6. rerank ColBERT reorders the top 25; exact promotion and coverage apply again
  7. page ranks are assigned before the page is cut

Measured, not promised*

Each of the 2,000 passages of tiny-embedding-bench-v1 (opens in a new tab) is indexed once, and 1,000 questions in 20 languages search them. R@k is the share of a language's 50 questions whose gold passage, in the question's language, ranks in the top k. Lexical search knows the question's language; vector search scans every passage, so a question also competes with the 19 translations of its gold passage. From make bench, version 0.4.0.
